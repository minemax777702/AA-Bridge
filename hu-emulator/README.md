# CarbitLink HU Emulator 0.1.0

Отдельное Android-приложение (Android 10+), предназначенное для проверки
AA-Bridge, а не для полной замены оригинальной прошивки CarbitLink.

## Сборка

```bash
./gradlew :hu-emulator:assembleDebug :hu-emulator:testDebugUnitTest :app:assembleDebug
```

APK: `hu-emulator/build/outputs/apk/debug/hu-emulator-debug.apk`.
Оба debug APK также публикуются как отдельные артефакты Android CI.

## Подключение двух Android-устройств через доверенный компьютер

1. Установить debug AA-Bridge на телефон с Android Auto; запустить сервер
   головного устройства Android Auto по обычной инструкции AA-Bridge.
2. Установить HU Emulator на второй Android-телефон/ГУ или Android Emulator.
3. Подключить оба устройства к ADB и посмотреть их serial: `adb devices`.
4. Отключить реальный автомобиль. В AA-Bridge: Настройки → Расширенные
   настройки → Отладка → Запустить сеанс эмулятора ГУ. Слушатель
   привязан только к 127.0.0.1, доступен только в debug-сборке, ожидает 2 минуты.
5. На компьютере выполнить команды (заменить PHONE и HU на serial устройств):

```bash
adb -s PHONE forward tcp:10920 tcp:10920
adb -s PHONE forward tcp:10921 tcp:10921
adb -s PHONE forward tcp:10922 tcp:10922
adb -s HU reverse tcp:10920 tcp:10920
adb -s HU reverse tcp:10921 tcp:10921
adb -s HU reverse tcp:10922 tcp:10922
```

6. В эмуляторе выбрать разрешение и возможности, адрес 127.0.0.1,
   нажать «Подключить». Для передачи звука в AA-Bridge заранее выбрать
   экспериментальный вывод через CarbitLink; для микрофона включить
   отдельную настройку CarbitLink mic и разрешить запись на обоих устройствах.
7. После теста остановить сеанс на телефоне, отключить эмулятор и удалить
   туннели (`adb -s PHONE forward --remove tcp:10920`,
   `adb -s HU reverse --remove tcp:10920`; повторить для 10921, 10922).
   Не использовать режим на недоверенном компьютере. Локальные приложения
   теоретически тоже могут обратиться к localhost во время debug-сеанса;
   протокол не аутентифицирован, не открывать порты в LAN.

## Что поддерживает первая версия

- TCP PXC: два канала, CLIENT_INFO, flags, heartbeat, ACK, PCM-потоки.
- Mirror: H.264 push mode, SPS/PPS, экран с выбором разрешения, Home/Back,
  передача отдельных touch slots включая мультитач.
- Music/TTS/VR/Talkie: отдельные выходы PCM; mic — 16 kHz mono только
  после запроса и при явно включённой настройке и разрешении.
- Имитируются потеря аудио ACK, задержка ACK 1500 мс, отключение сеанса.
- Журнал команд/размеров, не сырой звук. Ограничения размеров кадров,
  очередей ввода и PCM. Геопозиция не предоставляется эмулятору.
- Обычный Wi-Fi Direct режим AA-Bridge не ослаблен.

## Ограничения

Не подтверждена работа на физических устройствах. Эмулятор повторяет
известный протокол AA-Bridge и не доказывает совместимость реального ГУ.
Нет USB AOA host, автоматического mDNS/Wi-Fi Direct pairing, pull mode,
телеметрии, неизвестных кнопок и ночного режима. Обычная LAN не поддерживается
отладочным слушателем. На Android Emulator могут отличаться аудио, H.264
и доступ к микрофону. Не использовать при движении автомобиля.
