# Head-unit compatibility testing

Settings → Head unit compatibility. Presets: Automatic plus all 16 distinct manual combinations, grouped by audio route (direct Android Auto sound, Bluetooth preferred, phone speaker, experimental CarbitLink PCM). Each route has phone mic or HU mic priority, paired with native multi-touch or single touch. Manual settings retain the AUTO gesture value for compatibility; it uses the same native slot path as MULTI, so it is not duplicated as a separate preset. The microphone fallback and negotiated PCM capability gates remain unchanged. Automatic uses Bluetooth preference with phone fallback, only attempts HU microphone on an Android Auto voice request when HU explicitly advertises it, and uses native touch slots. PCM stays opt-in. Auto/multi touch use the same existing slot path; single-touch mode filters to one contact. QDLink's legacy single-contact path remains unchanged.

Reconnect the physical head unit after profile changes. On a parked vehicle, test music, navigation prompts, a voice request, and pinch/touch. Mark each result independently. Results are local, keyed by observed protocol/name and selected profile (not a globally unique HU identity). ACK or PCM reception is protocol evidence, not proof of audible sound or intelligible speech.

Debug only: enable Extended control capture, reconnect, export diagnostics. Capture inbound PXC, mirror control, QD JSON and selected QD binary headers; skips known PCM/video/touch/heartbeat payloads, caps logged previews and rate, redacts common identifier/secret field names. Unknown binary PXC payloads are metadata only. Nested JSON fields matching vehicle-state terms are recorded as **unverified candidates**. No undocumented probes, CAN commands, or fake parking values. A field absent from the wire cannot be obtained by this app. The existing diagnostic log rotation applies. Logs may still contain identifying or sensitive values; inspect before sharing. No automatic mic recording or uploads.

Real-car parking restrictions remain untouched. GPS speed is not proof of parking. The feature cannot guarantee discovery of CAN/OBD data on a HU that never forwards them.

## Diagnostics wizard

Open Settings → Head unit compatibility → Diagnostics wizard. Identify the connected, streaming HU and give the run a name. The wizard saves original settings, test progress and profile-specific answers locally across disconnects and app restarts. In debug it enables bounded control capture. Choose profiles in capability-informed order; disconnect fully before preparing a new profile, reconnect the same HU, then follow the music, navigation prompt, voice recognition, tap/swipe and pinch instructions. Single-touch profiles omit pinch by design. Audio results distinguish HU output from phone output. Skip and failed checks never count as passes. Results require a streaming session with the expected profile and matching capability fingerprint; fingerprint is not a unique device ID, so use the same physical HU. The wizard ranks only fully passed profiles as recommendations; prioritizes HU audio, verified pinch zoom and simpler transport on ties. It does not play arbitrary PCM, automatically record voice, send unverified probes, manipulate vehicle controls or bypass driving restrictions. Test using Android Auto's actual playback and input path. A recommendation is applied only by explicit action while disconnected; original settings can be restored. Export the diagnostics ZIP to include wizard verdicts and bounded protocol evidence. The saved run can be resumed or deleted (with original settings restored) while disconnected.

## Advanced tests

The wizard has an expandable automatic/manual test panel. Exit Android Auto on the head unit without disconnecting, stop other playback and lower volume before running generated signals. System, speaker and Bluetooth use Android AudioTrack; PCM MUSIC (48 kHz stereo) and TTS (16 kHz mono) use existing negotiated CarbitLink streams only. No guessed formats, forced capability flags or audio recording. A successful send is not proof of audibility. Manual verdicts are logged. Auto sequence tests each route; each can also be invoked separately. The ordinary Android Auto functional tests remain required for recommendations.

Calibration: nine targets on the real HU virtual display, five for fitting axis swap/inversion/scale/offset, four for independent validation. Correction is explicit, only for the current link, reset on disconnect or screen size change. Invalid fit cannot be applied. The panel can stop/reset calibration. This tests mirror coordinates, not Android Auto crop margins.

Protocol comparison: import an authorized original text trace (not PCAP, APK, or encrypted capture) and an AA-Bridge log, or use latest local log. Canonical lines: RX PXC 0x10010 len=80; TX PXC 0x10011 len=32; channel MIRROR, QD-BIN, QD-JSON, QD-HU also accepted. Direction is relative to the phone. Legacy AA-Bridge PXC/MIRROR log lines supported. Shows opcode presence and observed payload lengths; bounded/sampled logs do not prove that a command is unsupported. Outbound PXC and mirror control metadata added in debug extended capture. No reference capture is bundled and no interception of other apps is performed.
